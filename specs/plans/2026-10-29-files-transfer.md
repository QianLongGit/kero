# Files View Download & Upload Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Download…/Upload Here… context-menu actions to the Files view for remote hosts, backed by a raw binary transfer stream over the existing yamux connection.

**Architecture:** One new connection kind (`transfer`) dispatched in `Daemon.serveHello`; JSON header lines reuse the `proto.Request`/`proto.Message` envelopes (old daemons answer "unknown method" for free); payloads are declared-length raw bytes. Root-package `files_transfer.go` speaks the wire directly on the `net.Conn` from `host.dialer()` and drives dialogs, progress, and refresh.

**Tech Stack:** Go stdlib only (`archive/tar`, `filepath`, `io`); mygo `Dialog`/`ui`; locales via `mygo generate`.

**Spec:** `specs/2026-10-29-files-transfer-design.md` — the plan argues from it; executors read both.

## Global Constraints

- English comments, why-focused, matching neighboring files; minimal diff to untouched code.
- One feature per root-package file: new code goes in `files_transfer.go` + `files_transfer_test.go`.
- `proto.Version` stays 3 — no bump (spec: Protocol).
- `locales/catalog_gen.go` is generated by `mygo generate` only, never hand-edited; `en.json`, `zh-Hans.json`, `ja.json` change together.
- Root tests isolate with `t.Setenv("KERO_HOME", t.TempDir())` (+ temp `KERO_CONFIG`), per repo convention.
- CI equals `go vet ./...` + `go test ./internal/...`; root tests run locally (`go test .`).
- **No git commits or branches** — the user commits manually; every "Commit" step below is replaced by the listed verification commands.
- JSON tags follow the existing `internal/proto` struct style (`json:"path"` lowercase keys).

## Review Focus

1. **Old remote kerod** — hello `transfer` coerced to control must answer `unknown method` for `transfer.download`, which the client surfaces as the existing update-host error. Pinned in Task 2.
2. **Tar path traversal** — a hostile/broken remote streaming entries like `../evil` or `/etc/x` must be rejected during untar; nothing written outside the destination. Pinned in Task 6.
3. **Upload collision** — an existing remote file of the same name must never be overwritten; daemon-side dedup produces `name copy.ext`. Pinned in Task 4.
4. **Body truncation** — daemon dying mid-body (short read) must error and leave no file at the final local/remote name (temp+rename both sides). Pinned in Tasks 4 and 5.
5. **Zero-length file** — size 0 round-trips both directions without hanging on a zero-byte copy. Pinned in Tasks 2 and 5.

### Task 2: Daemon `serveTransfer` — single-file download + error paths

**Files:**
- Create: `internal/daemon/transfer.go`
- Modify: `internal/daemon/daemon.go` (`serveHello` switch, ~line 700)
- Test: `internal/daemon/transfer_test.go`

**Interfaces:**
- Consumes: Task 1 structs; existing `hostPath` (fs.go:30), `identity`, `serveHello`'s `net.Conn`/`*bufio.Reader`.
- Produces: `func (d *Daemon) serveTransfer(conn net.Conn, r *bufio.Reader, id identity)` — writes the Welcome itself (mirroring the control path), then LOOPS reading `proto.Request` lines from `r` until EOF or error: `transfer.download` serves its reply+body then returns (the client closes after one download); `transfer.upload` answers ready/body/done and continues the loop for the next file. Every body — both directions — goes through the SAME `r`/`conn` pair; bytes already buffered in `r` must never be bypassed by reading `conn` directly. Later tasks extend the dispatch, not this signature.

- [ ] **Step 1: Write failing tests** using the full-handshake pattern (owner_test.go:117-124 `serveDialer`: `net.Pipe` + `d.serve(there, identity{…})` on a `testDaemon(t)`):
  1. happy path: hello `{kind:"transfer"}` → request `transfer.download {path: <tmp file>}` → reply `Message{Result: TransferHeader{Size, Mode}}` → body bytes equal the file.
  2. missing path → `Message{Error}` contains "no such file".
  3. path outside any restriction — spec has no allow-list beyond `hostPath`; `~` expands like `fs.list` (assert `~/x` reaches the same file as absolute), with `t.Setenv("HOME", t.TempDir())` — `proto.Home()` reads the real HOME, not `KERO_HOME` (Windows: also set `USERPROFILE`).
  4. old-daemon pin: hello `{kind:"control"}` (today's coercion) → request `transfer.download` → `Message{Error}` mentions "unknown method".
  5. zero-byte file → header `{Size: 0}`, empty body, clean EOF.
- [ ] **Step 2: Run** — `go test ./internal/daemon/ -run Transfer -v` → FAIL.
- [ ] **Step 3: Implement** — `serveTransfer` + a `transferDownload` helper (`os.Stat` via `hostPath`; file: write `Message{Result: TransferHeader{Size, Mode}}`, `io.Copy(conn, f)`); hook `case proto.KindTransfer:` into `serveHello` before the control default, and keep the `kero clients` accounting honest: daemon.go:687-691 normalizes every non-attach kind to "control" — let `transfer` be recorded as itself. Directory paths reply `Message{Error: "is a directory"}` for now (Task 3 replaces).
- [ ] **Step 4: Run** — same command → PASS; `go vet ./internal/daemon/`.

### Task 4: Daemon upload (ready hop, temp+rename, dedup)

**Files:**
- Modify: `internal/daemon/transfer.go`
- Test: `internal/daemon/transfer_test.go`

**Interfaces:**
- Consumes: Task 2 dispatch; Task 1 `TransferUploadParams`/`TransferUploadDone`.
- Produces: behavior — `transfer.upload {dir, name, size, mode}`: validate dir (exists, is dir) and name (`filepath.Base(name) == name`, non-empty) → reply `Message{Result: TransferHeader{}}` (ready) → read exactly `size` bytes → write to temp file in `dir` → rename to `dedupName(dir, name)` → reply `Message{Result: TransferUploadDone{Path: final}}`. Also unexported `dedupName(dir, name string) string`.

- [ ] **Step 1: Write failing tests**:
  1. happy path: bytes land at `dir/name` with mode preserved; final path in reply.
  2. collision: pre-create `dir/name` → final is `dir/name copy.ext`; pre-create that too → `name copy 2.ext` (same shape as files_menu.go paste naming).
  3. bad dir → `Message{Error}` BEFORE ready, client sends nothing.
  4. truncation: client closes after half the bytes → no `name`, no `name copy*`, no leftover temp file (`os.ReadDir` the dir).
  5. zero-byte upload → empty file at final path.
- [ ] **Step 2: Run** → FAIL.
- [ ] **Step 3: Implement** — reuse the temp+rename shape from `fsWrite` (fs.go:175-189); `dedupName` probes with `os.Stat`; mode from params via `os.Chmod` before rename (or `OpenFile` with perm — implementer's choice, test only asserts final mode). The body MUST be read through the stream's `bufio.Reader` — `io.CopyN(tmp, r, size)` — because the request line and the first body bytes share `r`'s buffer; reading `conn` directly loses buffered bytes. After the done reply, the request loop continues with the next file.
- [ ] **Step 4: Run** → PASS; `go vet ./internal/daemon/` and `go test ./internal/daemon/`.

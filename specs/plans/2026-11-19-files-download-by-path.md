# Files: Download by Path Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Files view of a remote host gains a "Download by Path…" dialog: one typed path — relative to the folder shown, absolute, or `~/` from the home — is checked by `fs.stat` and, when it exists, downloads through the existing `downloadFrom` flow untouched.

**Architecture:** One root-package file (`dl_by_path.go`) holds a small dialog state on `filesState`, a submit flow that calls the existing `fs.stat` RPC (`FSStatParams{Path, Base}` — the daemon already resolves `~`, absolute and Base-relative paths) and dispatches to `downloadFrom(h, st.Path, st.Dir)`; a `DialogBase` view beside the palette/picker ones; and two entrances on the Files root row (a fifth icon button, and a ContextMenu item beside Upload Here). `downloadFrom`, the busy gate, the Save dialog, the folder picker, the xfer row and every toast are reused with zero changes.

**Tech Stack:** Go stdlib; mygo `ui` (DialogBase, TextInputBase, NewTester); locales via `go tool mygo generate`.

**Spec:** this plan is self-contained — the adjudicated decisions below are the spec; there is no separate design doc. Executors read this file only.

## Adjudicated decisions (verbatim from the user — do not relitigate)

1. **Interaction = Plan A:** a fifth `iconButton` on the root row (narrow the Preview button's padding if the row gets tight) → a `DialogBase` dialog with a single path input (its placeholder explains "relative to the current folder, or absolute") → Enter or Download → `fs.stat` validation → on success `downloadFrom(h, st.Path, st.Dir)` (**downloadFrom itself changes not at all** — busy gate, Save dialog, folder picker, xferRow progress and toasts are all reused); on failure, red text inside the dialog (the picker's own precedent, picker.go:195) and the dialog stays open.
2. **Two entrances:** the root-row icon button plus an item on the root label's ContextMenu (beside Upload Here, files.go:219-225).
3. **Files and directories both** — `st.Dir` routes the Save dialog vs the folder picker, naturally.
4. **No keyboard shortcut in v1** (YAGNI); no palette command.

## Global Constraints

- English comments explaining why, matching neighboring files; minimal diff — `downloadFrom` and everything under `internal/` are untouched: the feature adds no RPC (fs.stat is already there, internal/proto/remote.go:131-142) and no setting, so kerod's build fingerprint does not move.
- One feature per root-package file: new code goes in `dl_by_path.go` + `dl_by_path_test.go`; `files.go` gains the state field and the two entrances, `view.go` one mount line, `palette.go` one condition, `icons.go` one icon.
- `locales/catalog_gen.go` is generated by `go tool mygo generate` only, never hand-edited; `en.json`, `zh-Hans.json`, `ja.json` change together.
- Root tests isolate with `t.Setenv("KERO_HOME", t.TempDir())` via `testApp` (already the helper's own doing); root tests run locally (`go test .`), CI runs `go vet ./...` + `go test ./internal/...` — which this feature cannot break, as `internal/` is untouched.
- Before touching UI code, read `.agents/skills/mygo-maintenance/SKILL.md` (Bind/FocusBind, element lifetimes, `ui.NewTester`); `go tool mygo vet .` must stay green.
- A fake `fs.stat` in tests must answer with the daemon's real response shape (the fetchDir-race false-red lesson): the fixture resolves `Path`+`Base` as the daemon's `hostPath` does (internal/daemon/fs.go:30-44) and returns a normalized absolute `Path` with `Exists`, `Dir`, `Size`.
- Tasks 1–3 make **no git commits** — the user commits manually; each task's last step is its verification instead. Task 4 (release) commits per the runbook, as the user's standing release workflow authorizes.

## Review Focus

1. **A path that is not there** — red text naming the miss, the dialog stays open, busy clears, nothing downloads. Pinned in Task 1 (`TestDlByPathNotFoundStaysOpen`) and Task 2 (`TestDlByPathDialogErrThenOk`).
2. **Not connected** — the entrances toast `HostNotConnected` and never open the dialog; a connection lost while it is open shows red text, not a crash or a silent close. Pinned in Task 1 (`TestDlByPathNotConnected`) and Task 2 (`TestDlByPathEntranceNotConnected`).
3. **A stale stat answer** — the dialog closed (Esc) or reopened before the goroutine lands: the old answer must not color the new dialog red nor start a download. Pinned in Task 1 (`TestDlByPathStaleAnswerDropped`).
4. **File vs directory routing** — a file goes to the Save dialog (`xferSave`), a directory to the folder picker (`xferPick`), and `downloadFrom` receives `st.Dir` as its `isDir`. Pinned in Task 1 (`TestDlByPathResolvesPaths` asserts which dialog fired).
5. **This machine's Files view** — the local host shows no fifth button and no menu item (it needs no download). Pinned in Task 2 (`TestDlByPathLocalHasNoEntrance`).

```go
// dlByPath is the Files tab's download-by-path dialog (dl_by_path.go):
// one path typed, checked against the host before it downloads.
type dlByPath struct {
	open  bool
	host  *host  // the remote it downloads from; nil never while open
	base  string // the root the tree showed: a relative path's base
	query string
	err   string // why the last path did not download, shown in red
	busy  bool   // a stat is under way; the Download button waits
	gen   int    // counts openings; an answer from a dialog since closed is dropped
}
```

`filesState` gains `dl dlByPath` after `xfer` (files.go:57), with a one-line why comment beside the neighbors'. And:

```go
// dlByPathSubmit takes the dialog's query to the host: fs.stat says what
// the path names — the daemon resolves a relative one against Base, and
// ~ and ~/… as the home's — and what exists downloads, files and folders
// both, through downloadFrom as its own menu item does. What does not
// stays in the dialog, told why in red.
func (a *App) dlByPathSubmit()
```

Behavior the tests pin (the body follows from them):
- Trim the query; empty or `busy` → return. `h.cl == nil` → `err = locales.HostNotConnected(h.name)`, stay open (no goroutine).
- Else `busy, err = true, ""`; on the goroutine `cl.Call("fs.stat", proto.FSStatParams{Path: q, Base: d.base}, &st)` (build the params **before** `go`); back on `a.update`: `!d.open || d.gen != g` → drop; `err != nil` → `err = remoteError(err)`; `!st.Exists` → `err = locales.FilesPathNotFound()`; else `open = false` and `a.downloadFrom(h, st.Path, st.Dir)` — on the UI thread, as the menu's own chosen item does (files_menu.go:52-55). `busy` clears on every non-dropped answer.
- Locale keys (all three catalogs, beside the `filesTransfer*` block ~en.json:740-786): `filesDownloadByPath` "Download by Path…", `filesDownloadByPathDetail` "Any file or folder of the host: a path relative to the folder shown, an absolute one, or ~/ from the home.", `filesDownloadByPathPlaceholder` "path/to/file, /absolute, or ~/from/home", `filesPathNotFound` "No file or folder at that path". zh-Hans: "按路径下载…" / "主机上的任意文件或文件夹：相对当前目录的路径、绝对路径，或 ~/ 开头的家目录路径。" / "相对路径、/绝对路径 或 ~/家目录" / "该路径下没有文件或文件夹"。ja: "パスでダウンロード…" / "ホスト上の任意のファイルやフォルダー：表示中のフォルダーからの相対パス、絶対パス、~/ から始まるホームのパス。" / "相対パス、/絶対パス、~/ホーム" / "そのパスにはファイルもフォルダーもありません"。

```go
// relative against the base the dialog opened on, absolute as typed
// (cleaned), ~/ from the home; a folder picks the picker, a file the
// Save dialog — downloadFrom's own routing, unchanged.
func TestDlByPathResolvesPaths(t *testing.T) {
	for _, tc := range []struct{ name, query, want string; dir bool }{
		{"relative", "notes.md", "/srv/proj/notes.md", false},
		{"absolute", "/etc/app.conf", "/etc/app.conf", false},
		{"home", "~/backups", "/home/u/backups", true},
	} {
		t.Run(tc.name, func(t *testing.T) {
			f := newFilesHost(t)
			f.files["/srv/proj/notes.md"] = []byte("n")
			f.files["/etc/app.conf"] = []byte("c")
			f.dirs["/home/u/backups"] = true
			// the fakes: which dialog answered, and that downloadFrom ran
			f.a.side.files.dl = dlByPath{open: true, host: f.h, base: "/srv/proj", gen: 1, query: tc.query}
			f.a.dlByPathSubmit()
			f.waitsFor(t, func() error { /* dialled && slot released */ })
			// assert: dialled; saved == !tc.dir && picked == tc.dir; dl.open == false
		})
	}
}
```

- **`gen` must never reset** — the stale-answer drop depends on `gen` being monotonic for the app's life; `downloadByPath` writes a whole new `dlByPath` but copies `gen` incremented. A tempting "reset on close" reopens the collision where a closed dialog's late stat answer colors a reopened one (the exact bug `TestDlByPathStaleAnswerDropped` pins).
- **Dialog close timing rides pickerView's verified shape** — the post-`DialogBase` tail (`if submit` / `if !d.open { a.focusTerminal() }`) works because the picker's own tail (picker.go:237-249) works; do not move it before the `DialogBase` call or into the `open` guard.
- **`busy` replacing the button with a spinner** can shift the row's height by a pixel or two — acceptable; if it flickers in QA, size the spinner to the button's 30 rather than gating layout.
- **The UI tests lean on the fixture's pane ownership** — the session's first pane belongs to `f.h` via the fixture's owner map (files_open_test.go:68); if `testApp`'s initial layout ever changes, the helper's setup follows it (find the pane `filesRoot` resolves to rather than assuming index 0).
- **Right-click by label** — the root label's shown text is `h.shortDir(root)`; the test computes it (`f.h.shortDir("/srv/proj")`) instead of hardcoding, so a `shortDir` change cannot falsify the test.
- **`filesPathNotFound` is this dialog's own wording** — fs.stat cannot say why a path misses (permission vs absent); the red line says "no file or folder at that path", and an error the wire does report goes out as `remoteError` verbatim. Do not invent a second, sharper message; that is a new decision if QA asks for one.
